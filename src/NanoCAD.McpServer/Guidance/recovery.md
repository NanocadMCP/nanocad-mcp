# Continue from the actual receipt

Keep the original tool name, operation_id, full payload, bridge lifetime and returned identities. Read success, data.status, error.code, error.details.outcome when present, context, receipt and warnings together. A timeout, retryable flag or missing observation alone does not establish whether a write ran. get_operation_result retrieves the existing historical receipt by bridge lifetime and operation_id without replaying the payload or accessing CAD. If details were omitted to fit transport bytes, use its references/warnings pages; a missing entry leaves the outcome unknown.

| Observed receipt or condition | Safe continuation |
| --- | --- |
| data.status=committed, or completed for manage_document | Preserve the recorded outcome. Use returned identities and current context to inspect the requested result; do not duplicate the write. A replay describes the original execution, even if the user later used Undo. |
| WRITE_OUTCOME_PENDING | Native work is still pending; error.details.outcome may be unknown. Wait using get_operation_result with the original bridge_instance_id and operation_id. Exact same-tool/ID/payload replay remains available in that bridge lifetime. Do not change expected_revision, start dependent edits or restart nanoCAD. A client timeout does not cancel native work. |
| WRITE_OUTCOME_UNKNOWN or error.details.outcome=unknown | If the response was lost, use get_operation_result (or exact payload replay) to retrieve the existing receipt. If the final receipt still reports unknown, inspect only affected geometry, history, expressions and references from its stage/cause/partial identities. Do not infer success, failure without changes or rollback, or submit replacement work with a new ID before reconciling actual state. |
| error.details.outcome=not_started | This execution did not start. Correct the actual input or obstacle, refresh the intended context as needed and use a fresh operation_id for the corrected write. Replaying the old ID returns its original outcome. An empty Undo step may still exist. |
| error.details.outcome=rolled_back | Accept only the explicitly reported rollback scope; it does not guarantee Undo availability or an unchanged Undo history. Correct the cause and read current context before a new write. Never infer this outcome from a generic error. |
| STALE_DOCUMENT or stale editing references | Refresh the intended document and required object/token reads. Correct a write with a new ID only after the earlier receipt establishes it did not execute; a stale read does not resolve an earlier unknown write. Never redirect to another document or change a pending replay payload. |
| Known committed receipt with details_omitted=true | The write committed; bulky details and original detailed warnings may be omitted. Inspect affected objects using known request/source identities and targeted discovery where generated IDs are missing. Do not split and resubmit the committed work, assume atomic rollback or guess new identities. |
| COMMAND_COMPLETION_PENDING on a committed receipt | Commit is recorded but command completion is still pending. Wait for completion and refresh document state before another write. Do not recreate the result. |
| A post-commit verification/cleanup warning | Keep the committed outcome and inspect returned affected objects and actual task requirements. An unavailable check is not rollback; a confirmed invalid shape or lost meaningful link still needs correction. |
| An explicit external approval rejection | Preserve its exact reason separately from native write receipts. Do not repeat the rejected payload or change its ID to evade review. Where the decision permits checks, resolve the stated concern with new evidence; if authorization remains missing, request only that concrete narrow decision. A missing bridge-ledger entry alone still means unknown. |

Use a fresh operation_id only for new work. Never replay an ended bridge lifetime. get_status reports connection and active work; it does not retrieve a completed receipt by operation_id. Preserve original receipts when reconciling state; a later successful correction does not retroactively establish an earlier unknown outcome. Unknown/unavailable observations are not empty geometry, constraints or dependency networks.

Reconciliation has a concrete endpoint: establish what is present now, what remains to meet the task, and whether the intended next operation has the required actual geometry, owner, sources and controls. Use targeted observations of the affected group and a meaningful image; an Ok status alone is insufficient. If this establishes a valid continuation, keep the old historical receipt unknown and perform only the remaining work with fresh references and operation IDs. A permanently unknown historical receipt alone does not require abandoning an otherwise established current model or asking for new consent. The user's answer cannot establish whether an earlier operation ran and does not replace this reconciliation.

For all operations, ROLLBACK_NOT_GUARANTEED and missing Undo are recovery warnings, not by themselves a reason to refuse, disable a supported operation, demand additional permission or delegate it to manual actions. Execute task-authorized work with a brief disclosure. Ownership, actual dependencies, invalid input and critical failures still require their specific correction. Never promise atomic rollback or recreate the whole drawing to recover an uncertain action.

Creating a requested part includes its necessary additions, cuts, patterns, finishing, parameter changes and corrections even when the operation edits the newly created body. It includes cleanup of the task's own proven-unused temporary objects after checking consumers, while preserving reference/source geometry and unrelated existing content. The command's modify/edit name and lack of rollback do not create a new permission boundary. Ask for a decision about a material scope change or unresolved requirement, not renewed authorization for ordinary steps already included in the task.

# Recover the affected native model

To remove an obsolete complete native model, use ordinary erase with its current top-level model handle, including Sweep roots, in an erase-only batch. delete_model_feature instead removes a selected eligible feature and retains its part. An external consumer or shared auto-erased sketch source is an actual dependency to resolve. Inspect those references and include additional sources/models only when their removal belongs to the user's intended work. Native-owned cleanup is observed after command completion; use reported retained auxiliary IDs rather than assuming every hidden construction object was removed.

For a planned Model Space erase or one rejected over uncertain dependencies, explicitly read inspect_objects with erase_assessment=true and the full intended handle set together. Ordinary Paper erase retains its existing supported active-space, owner and dependency checks without that flag. Reuse actual creation/Boolean-result receipts and surface each selected handle's task provenance, current role, retained-consumer evidence and the deliverable bodies that will remain. A layer name, hidden display or creation during this task alone does not prove disposability. An eligible assessment is technical admission for the observed context, not user authorization or an override of an external rejection. Blocked or unavailable assessment is not clearance. Retry only after resolving the exact objection through new evidence or narrow explicit approval; approval resolves authorization only and does not replace missing technical evidence. Preserve useful sources, shared inputs and unselected model dependencies.

For readable native history with NeedUpdate, use modify_entities operation=rebuild_model with the current body handle and last_item_id before requesting manual updating. It requests one native part rebuild in immediate mode while preserving intentional suppression. Read native_rebuild_accepted, model_healthy and unresolved_nodes: an accepted rebuild can leave construction needing correction. Inspect the indicated feature, prerequisites and affected geometry, plus the actual expression/dimension of any preceding unknown write. Do not duplicate that write, repeatedly rebuild unchanged failed geometry or replace the part. After recovery, use fresh context and existing feature/parameter editors; native unsuppression eligibility still applies.

For an existing sketch's lost face support, explicit set_model_sketch_support recovery uses the observed sketch/old-support IDs and an actual healthy WorkPlane/token. frame_reference_policy defaults to preserve. use_target_datum explicitly retires the observed old point/axis/second-axis placement references so the chosen datum's actual native frame defines the sketch placement; it keeps internal sketch controls and other meaningful dependencies. Recovery-datum preparation can return already captured frame_references alongside local geometry and controls for this decision. An absent observation is unknown, not an empty reference set. Do not infer former WCS placement from local coordinates or silently select replacement-frame mode after a failed preservation attempt. Read the actual outcome and reconcile any unknown before continuing with the intended remaining repair.

NATIVE_PROXY_PRIVATE_STATE_UNOBSERVED means public resident identity/owner paths, class/flags and readable references were checked, while proxy-private payload bytes remain unobserved. NATIVE_PROXY_REFERENCES_UNRESOLVED retains explicit null, erased, foreign or unavailable stored references; these are not healthy targets or owned objects. Neither warning alone proves a failed edit or complete private-data preservation. Continue from the actual outcome, owning controls, meaningful geometry and retained relationships. Missing/foreign part, sketch, profile or control identities, changed meaningful links and an invalid result still require correction.

If restoring the required parent or suppressing selected construction is the needed correction, set_model_feature_suppressed accepts NeedUpdate within its exact same-part dependent closure while preserving other suppression choices. Inspect IDs, expected flags and prerequisites first; do not hide unrelated failures or force an unsafe restoration. For an intentionally obsolete terminal Mirror, delete_model_feature has its own fresh deletion-token scope and retains source features. Prefer these native operations over manual history-tree actions or whole-part recreation.

After unknown model creation, read the returned stage and partial identities, then reconcile the affected body and its document construction. A missing or empty body is not proof of no changes: standalone sketches, profiles and retained drawing sources can exist outside its history. Use the relevant document sketch/profile inventory and exact IDs when available. Do not start replacement creation or remove partial objects until their actual role and ownership are known. A preparation or registration failure does not establish a constraint-solver defect. An alternative must address the actual obstacle and preserve the requested controls and dependent behavior; independent geometry or an unconstrained profile is not equivalent to a controlled part.

If an operation is genuinely unsupported, use a supported route meeting the same requirements or explain the missing capability; agree before a material compromise. Isolate crashes, invalid geometry or lost meaningful relationships to the affected action. A bounded warning or diagnostic discrepancy does not disable an entire working family.

# Resolve the actual external obstacle

For HOST_BUSY or a dialog, request the specific necessary user action and continue independent work. If no bridge is available, ask the user to open nanoCAD and finish startup dialogs; the installed integration should load automatically. Address a persistent installed connection issue rather than asking an engineer to develop/load DLLs or experimenting with APIs. Never use screen/input automation. Before any necessary restart after pending work is resolved, save all open documents; preserve unnamed documents as DWGs in the project's recovery folder. Do not discard unsaved work or delete user files.

For ANALYSIS_LIMIT_EXCEEDED, distinguish the selected request from the whole document. Split/page only when it preserves intended dependencies and scope. Do not delete unrelated geometry, simplify the promised design, substitute hand-built primitives or retry the unchanged request to evade a limit. Report the exact affected scope and continue independent work. For RESPONSE_LIMIT_EXCEEDED on a write, preserve the exact request and outcome uncertainty; it is not advice to resubmit smaller write batches. Read responses can use smaller pages where supported.

For unavailable capture, use its error and intended document/view to request only the necessary window action. Metadata or an empty/stale image is not visual review. After sleep/wake, a fresh frame with matching camera metadata may still show an earlier view or omit an already verified change. Recapture once without repeating model or view writes. If it remains stale, report the visual limitation and choose further action from actual document/operation state; background capture remains available. Keep recovery bounded; it is not an assignment to test Undo, save/reopen, replay or restart.

Attribute an approval block only to an explicit approval requirement or actual rejection from the external system; MCP warnings, eligibility guards and unknown outcomes do not establish one. Report the external source and its stated reason accurately. Do not bypass it by disguising or repeating the blocked action. Where permitted by the external decision, resolve the stated concern through actual checks and make the continuation reviewable: establish existing feature membership to rule out duplicates, or distinguish sketch coordinates, extrusion direction and width/depth when interpreting a cut. Continue useful independent work. If a required authorization remains missing, request that concrete decision with its real reason; do not substitute a generic Undo question.
