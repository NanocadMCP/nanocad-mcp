# Plan the complete editable drawing

Choose what the requested dimension or note change must affect before selecting an editor. All operation names below belong to modify_entities except the separate set_model_parameter tool. Read the chosen exact variant for its scope and fields.

| Intended change | Existing route and relevant observation | Effect |
|---|---|---|
| Dimension wording | replace_dimension_text; current override and placement | Keeps measured geometry; use the permitted measured-value placeholder, never a false literal dimension |
| Dimension appearance or position | set_dimension_format / set_dimension_display / set_dimension_line / set_dimension_text_position; actual definition, effective format and placement | Changes annotation presentation, not source geometry; the text-position editor selects DIMTMOVE=2 |
| Independent dimension measuring points | set_dimension_definition; complete current geometry.definition | Changes the dimension definition, not the source geometry or an automatic association |
| A dimension following supported drawing sources | associate_dimension / update_dimension_association / detach_dimension_association, or associations during supported creation; current geometry.association and actual source snaps | Source-to-dimension dependency, not a dimension-to-source driver; initial points must already match snaps |
| A drawing-geometry driver | set_drawing_dimension or set_drawing_expression; inspect_constraints and actual connected sources/consumers | Changes constrained geometry within the selected native network; source/formula propagation scope differs by editor |
| An internal sketch or model driver | set_sketch_constraint_parameter or set_model_parameter; actual history, control token/variable, units and consumers | Changes a supported retained driver; read parametric help for literal/formula and rebuild scope |

Plan all requested views, sections, details, dimensions and notes as one readable group. Use functional/manufacturing/inspection datums and measurable features; avoid ambiguous or redundant chains, overlapping labels and crossing leaders. Consider existing sheet content and available space before writing. Reuse suitable layers/styles/blocks. Reconcile projection directions with model axes; names alone do not establish orientation. Hatch actual cut material including openings. Follow the specified GOST/ISO/company practice, verifying normative claims from authoritative sources rather than inventing fits/tolerances. Produce editable DWG; printing/PDF are outside scope.

For drawing reconstruction or conformity, examine ALL supplied views and sections/details/notes and account for EVERY supplied dimension, including locations, hidden depths, radii/chamfers and thread callouts. Verify against final geometry or valid drivers, not only input values/labels. Distinguish unresolved requirements from completed ones. A drawing dimension formats/measures geometry; it does not drive the part. Use explicit supported source associations when following drawing geometry is required; ordinary annotation on a projected model view does not automatically acquire a model association.

# Views, sections, sheets and viewports

Use a suitable native projection/section operation before drafting substitute linework. Read get_drawing_views actual projection planes, scales, tree/alignment and explicit sources. Exact projected geometry uses pages: continue next_index under the same document/revision/layout/view. Native projection element order is not a persistent edge identity. Place independent annotation from actual geometry; after model edits refresh projections and update affected dimensions/notes.

create_drawing_views creates a fresh native group from explicit top-level Model sources. For a real group on an existing sheet, activate the ordinary Paper layout outside its model viewport, then specify target_space=paper with layout_handle. Origins are sheet XY, projection basis is WCS. Returned native owner sheet is distinct from Model source ownership. Optional source_identity_view_handle reads one view's simple/complete-complex/Section-sliced inventories; native Section source-generation settings, complete participation and sliced intersections have different meanings. Null/empty/unavailable projections are disclosed, not proof of a visibly useful view. Retained transfer between layouts has no supported native affinity-preserving route; never reset an owner or erase/recreate the original to simulate it.

Use rename_drawing_view, add_drawing_view_child or set_drawing_view_sources for the corresponding existing-group change. Read fresh tokens, sources and parent/child tree; source edits select the complete root/descendant group. Use set_drawing_view_properties for supported placement, scale and line display, planning affected aligned children together. Delete a requested ordinary leaf/subtree through delete_drawing_views while preserving its 3D sources.

create_section_view documents a planar cut when the complete native Model solid composition belongs in the intended detail, leaving model geometry intact. source_handles declares this composition. A selected subset with other visible Model solids on on/thawed layers is not retained by the current native root Section path and stops before object changes with SECTION_SOURCE_SELECTION_UNSUPPORTED. Do not add unrelated bodies to the requested detail or change their global visibility to bypass this limit. Hidden/off/frozen state alone does not prove a narrower saved source scope: complete actual native view participants must establish it. Unique fresh Section generation settings record the requested sources in every mode, with current type2D and live sectioning disabled; those settings and the sliced intersection list are separate from complete projection participation. Existing Section settings and new destination/appearance defaults remain checked. Optional source_identity_view_handle reads the actual simple/complete-complex view participants and stored settings separately; neither a cropped image nor one sliced source proves the retained projection choice. set_section_view_cut moves/resizes a retained ordinary non-live two-point Plane cut in its existing viewing/vertical basis. Read section_cut token and include all associated views/descendants with fresh layout/view tokens. The same Section/views, selected sources, placed planes/scales and history remain; native geometry refreshes. Global processing lists do not replace explicit projected sources. Live/support-driven/jogged cuts and layout transfer require other owning routes. Read fresh projected geometry and update independent annotation after a cut revision. Recovery/Undo is uncertain.

Use projected_diametric for an associative diameter on the active Paper sheet. Read the view with get_drawing_views and pass its current full circular-arc index, view handle and a sheet XY dimline_point for the text outside that circle. Select one visible circle in an ordinary unit-scale view of one local model solid. The writer verifies both opposite anchors on that native projection. Check the rendered diameter after a model edit.

Model units and sheet scale are separate. target_space=paper addresses supported content on the intended active sheet in sheet millimetres. A Paper dimension does not automatically measure Model through a scaled viewport; use an explicit supported scale interpretation. A paper viewport frames model content rather than creating native projected geometry. Use native viewport creation/copy/delete/camera operations with exact layout/viewport identities; copies keep model camera/scale/frozen layers/appearance and deletion leaves model/other sheet content. The overview viewport and linked/clipped/perspective contexts have separate scope. Observe Paper with top/preserve; a model camera inside its viewport uses the viewport adapter.

Standalone native drawings may follow supported part changes with multiple selected sources in Model or Paper. Other selected bodies retain observed geometry/metadata. Automatic caches refresh; manual/suppressed projections retain that state. Read unavailable-observation warnings honestly and inspect actual MCP pixels; cache/metadata checks do not certify complete follower preservation or visible geometry.

# Native dimensions, symbols and frames

For consistent notation, read current dimension_styles and prefer reusable native defaults through create_dimension_style or set_dimension_style_properties in modify_structure when appropriate. Specified tolerances belong to engineering requirements; style defaults do not change the part. Explicit overrides or literal text can retain earlier notation, so inspect effective affected dimensions and the rendered group after a style change.

Create the final native Hatch directly from existing curved sources with create_entities type=Hatch and boundary_groups when outline and holes are known. Native Polyline bulges, Circle/full Ellipse and Line/Arc chains are preserved; choose a real installed predefined pattern and island style. Use set_draw_order on actual returned handles when fills, outlines and notes need a different visible stacking order. Neither operation replaces geometry with drawn linework.

Read actual dimension kind, complete definition, measurement, effective format/display and native units before editing. set_dimension_definition keeps an independent dimension and changes its measured references using expected_definition. set_dimension_format changes supported effective style/sizes/precision/signed deviations; set_dimension_display changes units/rounding/factors/zero suppression/literal affixes/line visibility. Measurement remains separate: scaled labels do not convert or drive the part. Preserve style identity, plane and unrelated root/owned data. Only typed ACAD/DSTYLE pairs for requested display settings may change when the full effective readback agrees; equal-valued literal override vs inheritance is not certified.

Use native Dimension arc_length for ArcDimension arc length, with equal-radius endpoint rays in the selected counterclockwise sector; use jogged_radial for RadialDimensionLarge's true center/chord and its shortened representation. Dedicated definition/display/format keeps stored partial/symbol/leader controls. Ordinary move/rotate/positive uniform scale/copy retains mode flags/jog angle and active leader anchors. Partial start/end parameters are observed, but their transformed physical-span semantics are unverified; inspect actual partial arc/measurement after placement. Reflection and legacy extended text/line-position editing have separate scope.

Use native Tolerance to create a FeatureControlFrame from supplied native codes, an existing dimension style and XY oriented placement. set_tolerance uses fresh geometry.tolerance_token to revise its codes, placement/style/effective text settings. Preserve functional datum/tolerance meaning and the drawing's standard. Never invent a universal tolerance or reconstruct the frame from lines/text. These annotations do not drive source geometry or create automatic associations. Associated, field-bearing or annotative editing requires its owning adapter; unavailable reasons remain explicit. Inspect actual native rows, borders/symbols, readability and placement. Started recovery/Undo is uncertain.

Before writing annotation, choose a font supporting all actual required characters. TrueType glyph checks expose FONT_GLYPHS_MISSING; Unicode transport alone does not prove visibility. Prefer native automatic diameter/radius signs and measured values. Never knowingly write missing symbols, assume fallback or substitute a meaningful sign. set_text_style_font can select an installed compatible family with required_text in a separate request; changing a shared style affects its consumers and spacing. SHX/big-font, retained inline fonts and native frame control-code glyph semantics are not certified by the TrueType check. Do not report unverified coverage as checked; resolve notation/style and inspect meaningful symbols in the group image.

Thread/hole callouts must match actual feature parameters and intended representation. A native ThreadFeature designation or smooth cylinder does not prove a physical helix. Show repeated features and locating datums clearly; refresh affected drawings after feature edits.

# Native tables, notes and fills

For reusable schedules and callouts, read table_styles/mleader_styles and choose native create_table_style/set_table_style_properties or create_mleader_style/set_mleader_style_properties defaults in modify_structure. Table Title/Header/Data roles and supported MText callout frame/alignment/attachment defaults remain separate from explicit cell/content overrides. Plan readable content sizes and inspect the effective result. For Table formulas use set_table_cell_formula or the supported range editor; preserve dependent bindings instead of replacing evaluated values with displayed literals. Selected content/Field deletion uses its existing indexed editing eligibility.

For an existing planar contour, use the applicable native edit rather than reconstructing it. Offset retains its source and returns every result. Native trim/split/endpoint extension uses fresh geometry.native_curve.curve_token and the actual native interval; parameters are neither lengths nor normalized fractions. Meeting Line/Arc fillets/chamfers need both current tokens, explicit ends and actual radius/setbacks. In-place trimming and full-source retention are different choices. Read source/result provenance before dependent edits; these drafting operations do not create constraints or heal gaps. Detailed native Spline observation does not imply unrestricted legacy creation, transform or geometry replacement. Read the branch's exact owner/plane scope.

Create a real Table through create_entities, not lines/text: supply literal rectangular cells, placement/row/column sizes and an existing can_reference table_style from get_structure. Plan readable space. Existing native row/column insertion/deletion, merge/unmerge, text/value/formula/layout/grid/format/style operations use fresh geometry.editing.table_token and relevant raw metadata. A merged cell is addressed by its top-left anchor. resize_table changes physical sizes, not topology; ordinary indexed String/Long/Double slots retain their raw storage/order, cell arrangement, style and formatting. It also supports empty cells. Use a resize-only request for an indexed Table, with fresh expected_size for each selected zero-based row/column. Fields/block/formula/link sizing requires its scoped adapter. Native content/style/formula edits may reflow row heights/column widths; inspect reported/current sizes and readability. Use resize_table for an explicit required size.

set_table_cell_value stores typed scalar values/units/formats. set_table_cell_layout edits margins, rotation/scale, existing cell styles and data format without replacing values. set_table_grid_layout edits Single/Double native lines/spacing. Read raw values, units and expressions separately from display text; unit labels alone do not imply conversion. Same-table A1 arithmetic and native SUM/AVERAGE/COUNT support cell/range dependencies; the kernel evaluates. Aggregates ignore ordinary blank/String cells, while arithmetic inputs remain numeric. Missing evaluated values have an explicit reason and do not certify a calculated schedule.

fill_table_formula_range starts from its destination top-left expression; relative_references=true shifts unanchored refs and preserves $ row/column anchors, false repeats refs. Declare result storage units. Structural row/column edits retain numeric/formula schedules, formats and merges. References including $ anchors follow retained cells; interior insertion expands ranges and partial deletion contracts them. Deleted individual refs or whole ranges require formula_replacements at BEFORE-operation formula anchors using AFTER-operation coordinates before writing. New structural cells are explicit String/Unitless matrices; use native scalar/formula edits for numeric/formula content. Legacy Table RowType datatype/unit getters are unavailable; actual per-cell metadata remains checked. Fields/external data/multiple contents/arbitrary formula functions need their owning adapters. For TABLE_STATE_CHANGED read current token and changed components; it does not prove an earlier unknown rolled back.

Reusable TableStyle/MLeaderStyle defaults come from get_structure. Native creation/default edits keep actual owner dictionaries/consumers, content/anchors and observed distinct overrides; inherited layout may reflow. Assignment preserves explicit overrides, so inspect effective results separately from defaults. Read warnings about unobserved dynamic columns/equal-valued override masks/opaque field state. rename_table_style/rename_mleader_style keeps shared identity/references. set_current_table_style/set_current_mleader_style selects a working default with exact expected current handle, without assigning existing annotations or overriding explicit styles for new MCP content. External/custom owners or unclassified dependencies require their owning route; recovery/Undo is uncertain.

set_mtext_format changes an existing note's stored style/wrapping/spacing with its fresh geometry.formatting.editing.mtext_token while retaining raw inline content and native anchor. Reuse verified fonts/characters and inspect inline-font warnings without claiming full coverage.

set_hatch_properties uses fresh geometry.editing.hatch_token and retains loops/plane/supported local associations in Model or active ordinary Paper. Choose an installed predefined pattern/SOLID or omit pattern_name to keep a custom pattern. Angle is radians, origin_ocs belongs to its plane and pattern_space retains UserDefined spacing. Pattern availability is resolved in its drawing; detached preview failure alone does not justify reconstruction. This edits properties, not geometry.

set_hatch_boundary replaces the complete polygon/circle outline and holes of an independent Hatch in its retained OCS normal/elevation. Holes lie strictly inside without touch/overlap/nesting; empty holes removes them. Native identity/pattern/owned data remain, without new source curves/associations. Outer/ignore island style can hide stored holes; select intended properties and refresh token before boundary edits. Associative/annotative/gradient/field/unclassified dependencies need their owning route. erase removes native hatch/fill without deleting boundary curves unless requested. Recovery/Undo is uncertain.

# Existing structure and final review

Separate entity appearance, annotation format, reusable style defaults and model shape. set_properties changes supported visibility/line/layer/color/transparency; style assignment may retain per-object overrides. Choose the narrowest native operation. Rename reusable styles by identity, delete only unused records/empty inactive sheets when requested and preserve unrelated data. Change owned title-block labels with set_attribute_text and exact expected_text, keeping native anchor/style. Block writes select the intended active Model/Paper space.

rename_block_definition changes only the shared name of an ordinary local static definition, preserving insertions/attributes. Read handle/name and relevant occurrences first. Readable owners/metadata and available typed geometry remain checked; opaque field/native internals are disclosed. External text containing the old name is not rewritten. Dynamic/anonymous/xref/dependent definitions require another route.

Inspect one useful MCP image of the connected drawing group. Check projected form, all required dimensions/callouts, hidden features, signs, scale, spacing and readable fonts. Focus API reads on exact requirements or unavailable observations; do not turn annotation into an integration test or claim automatic association/manufacturing compliance from successful calls.

Native formula requests accept an optional leading =; the native Table setter receives one leading formula marker. The returned stored expression, native formula flag and reference/operator/anchor meaning are still checked. A finite displayed number alone never proves that a formula was stored. After structural changes, refresh the current table token and formulas before further work.

A native jogged-radius dimension may open through the SDK ImpDimension wrapper. Its exact native RX class is matched to RadialDimensionLarge before borrowing a non-owning typed wrapper for reading or the existing dimension edits. native_binding distinguishes the opened managed type from the verified definition type; the same resident identity/owner/plane/definition remains checked. Other proxy/custom dimension types are not inferred from their labels.

set_viewport_clipping edits the clipping link of an existing ordinary Paper viewport in place. Read get_structure section viewport_clipping and its current clipping_token; inspect_objects supplies geometry.native_curve.curve_token for a selected existing closed Circle/Ellipse/Polyline boundary. Activate the exact sheet outside a model viewport and use target_space paper. set_boundary assigns or replaces the same-sheet native link; enable/disable retain it, clear removes the link and preserves the boundary entity. Camera, scale, paper frame, native viewport/boundary identities and observed readable data remain checked; only the native association edge to this viewport may change. Boundary geometry and its unrelated links remain. Other sheet members retain membership/owner/type/basic appearance and viewport cameras; unrelated private/field data is outside this link-only edit. Viewport1, perspective/front/back-clipped or unresolved/foreign ownership need their owning route. This does not copy a viewport, transfer a layout, edit Model geometry or make annotation followers. Opaque native/field internals are unobserved. Recovery/Undo is uncertain; unknown is not success. Plan the visible detail and boundary against existing sheet annotations, then inspect one rendered group image and relevant readback.

A native same-table formula may create a local Field. Its actual cell formula flag/expression and Field identity, owner, readable unevaluated code/evaluator/format/options are retained in native_formula_field. Selected formula edits, formula-to-scalar replacement and explicit row/column deletion may change only their proved Field bindings/owned dictionary links. Unselected formulas and unrelated owned data remain guarded. Private Field data and child-field internals have no complete public inventory; this is disclosed rather than claimed exact. External/non-formula Fields and data links need their owning adapter. Inspect the stored schedule and native displayed values; an unknown write remains unknown.

After a verified defining-geometry edit, native dimension recompute may add new nonreferential XData application groups. Existing groups, root/owned data and links remain exact, and requested geometry/effective style are checked first. Added readable data is reported with a metadata-observation warning, without private-state or rollback claims. Lost/changed old groups, new object/handle/layer references and other metadata changes remain a preservation error.

set_hatch_association uses a fresh hatch_token to detach or rebind a retained native Hatch. Detach keeps stored fill and all source curves. Rebind takes one explicit outer and strictly inside, separate, non-nested holes in the current OCS plane and requested Model/active ordinary Paper space. Use outer_boundary_handle/hole_boundary_handles for closed zero-width Polyline, Circle or full Ellipse sources. Use outer_boundary_handles/hole_boundary_groups when a contour consists of a connected closed chain of separate Line/Arc sources; list each group in contour order, allowing either native direction of each member. The grouped form also accepts a single closed curve per group. Supply every retained hole in the complete replacement and keep sources distinct across groups. Native intersections and detached Region containment check topology; verified_boundaries identifies source types/roles, verified_loops identifies each requested group, and association_lifecycle.source_loops reads actual loop flags and IDs. Only this Hatch’s forward IDs and reverse source reactors change; shared local Hatch links/source geometry and readable owned data stay. Foreign/unclassified dependencies and annotative/field/gradient content need their adapters. Inspect the actual fill and links after the group; recovery/Undo is uncertain.
