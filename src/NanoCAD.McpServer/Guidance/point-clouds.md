# Read and measure a point cloud

For requested alignment or placement, use modify_entities with transform_point_cloud: WCS XYZ translation or arbitrary-axis rotation (angle in radians). This moves the drawing insertion in place, retaining its handle and shared source definition; it does not edit point data, import, reload or rewrite cloud storage. Ordinary move/rotate also work for WCS XY translation/Z-axis rotation without workplane. Refresh revision and all cloud cursors after placement before taking sections or measurements. A drawing opened read-only cannot change insertion placement; read-only source data is distinct from drawing write access.

PointCloud is a separate top-level section of the main command tree. Read `get_guidance(topic="commands", section="point_clouds")` for its compact tool/mode routes when needed; exact inputs remain available through `topic="schema"` for the chosen tool.

Use `query_objects` or the existing selection to find the cloud insertion handle. Inspect one top-level Model insertion with `inspect_point_cloud`; its definition handle and file path are different identities. Metadata reports an unloaded source as loaded=false with unavailable observations null; points and features require an already-loaded source. Keep the current bridge, document and revision in every request. These reads do not import, load missing files, change clipping or display, fit new features, create drawing geometry or save the drawing.

Start with `mode=metadata` to read the insertion bounds, source name/path and available native data. The reported native point counter is an observation, not the authority for whether a point traversal is complete. Drawing units are read from the drawing; the original scan's units may be unknown. Do not assume millimeters or silently rescale the cloud.

The bridge resolves point-cloud support from the running nanoCAD installation automatically; users do not need to load a helper DLL. This does not load a missing cloud source.

Use `inspect_point_cloud` with `mode=features` to read already-stored native feature IDs and geometry. Feature geometry carries its own native_feature frame; the insertion bounds use WCS. Do not treat those feature coordinates as WCS coordinates. An existing feature can provide an observed plane, cylinder or sphere; reading it does not fit raw points or establish that it matches the intended manufactured surface. A missing feature is not evidence that the physical surface is absent.

Use `analyze_point_cloud` with `units=drawing_units`. `mode=points` returns actual native point indices as decimal strings and coordinates in WCS. Request `include_attributes=true` only when the native attributes are useful; absent data must not be treated as zero. An index belongs to this cloud and revision, and is different from a page row number or an opaque cursor.

Use the returned point_wcs directly for sections and measurements. It comes from the insertion's native Vertex; do not apply the metadata transformation or back_transformation again. base_point and frame_observation retain separate native observations. A false or unavailable transform comparison is diagnostic and does not mean that the cloud is empty or that the returned points were rejected. Native rigid WCS insertion move/rotation and subsequent point/section coordinates were assessed in406. Shared, unloaded and other unassessed placement variants still need a task-specific check; do not apply the mapping twice.

For `mode=section`, supply a WCS origin, a nonzero normal, a perpendicular x_axis and positive thickness. The thickness is the total slab width, centered on the plane. The returned local axes are x_axis, normal cross x_axis and normal; local offset is the signed distance along the normal. Points retain their original WCS coordinates. An optional region supplies an inclusive WCS box and intersects the slab. This is a read of points in a layer, not a fitted contour or a new CAD Section.

Continue each paged read using its returned cursor with the same context, handle, mode, frame, filters and options. Feature pages return complete and next_cursor; analysis pages return scan.complete and scan.next_cursor. A page can be shorter than requested, or empty with complete=false, because a scan-time or response-byte budget was reached. This does not mean the cloud or section is empty. Finish the continuation until complete=true; reacquire context after a drawing change instead of reusing a stale cursor.

`mode=statistics` scans the requested region or slab. With query_point it searches for the nearest actual raw point in that subset. Bounds, counts and nearest point from an incomplete scan describe only the examined subset; they are final for the query only after `complete=true`. Completion means that the native iterator was exhausted for this query; it does not independently establish that every point in the original physical scan file is represented. A scan bound is not a fitted component dimension, and these results do not establish the original scan density or measurement accuracy.

For `mode=measure`, select one measurement kind. `point_distance` uses two indices returned from this actual cloud. `point_plane_distance` uses one such index and an explicit reference plane. `feature_diameter` uses an existing native Cylinder or Sphere feature ID. A native feature diameter whose mapping to the drawing frame is not established returns unavailable with a reason; native_value is a separate observation, not a usable WCS diameter. Refresh identities after a document change. Available linear results use drawing units; inspect the actual points or stored feature used by the measurement before using it as an engineering dimension. These operations do not create dimensions or claim a tolerance or feature-fitting accuracy.

For a requested drawing contour, choose a slab and region that isolate the intended surface, finish all pages and retain the actual section frame. Separate the component from adjacent surfaces before ordering its points. For an arc/line Polyline, prefer `create_entities` Polyline `construction=fit_points` with ordered section-local samples, explicit accuracy, corners and closure. Read the compact fit report; supplied-sample error does not bound unseen geometry or scan accuracy. Fit a separate engineering contour with ordinary `create_entities`; the cloud tools do not fit or create it. A smooth contour is not a mesh: do not connect raw samples or replace curved portions with dense short straight segments. When a smooth Polyline is requested, fit native circular arcs (bulges) and actual straight portions jointly with G1 tangent continuity; independently fitting neighboring arcs does not enforce that continuity. Use a native Spline only when the requested representation allows it. Preserve intentional corners, concavity and observed gaps; leave the profile open where the data does not establish closure. Choose fitting accuracy from the requested use and source quality, disclose consequential interpolation/root stations and do not invent a manufacturing tolerance or scan accuracy.

Check intended smooth joins before writing and after reading the actual native contour. For a directed planar Polyline segment, let phi be its chord angle and theta=4*atan(bulge) its signed arc sweep. Its forward tangent angles are phi-theta/2 at the start and phi+theta/2 at the end; a straight segment has bulge=0. Compare the incoming end tangent with the next outgoing start tangent in the same native plane, including the closing join of a closed contour. A reversal/cusp is not a tangent continuation. Reject degenerate segments from the smooth fit and correct actual discontinuities rather than hiding them with more vertices. Numeric comparison allows floating-point roundoff, distinct from the chosen point-fit tolerance. Report a significant remaining angular discontinuity instead of calling the contour smooth. Assess point-to-contour deviations, relevant dimensions and one useful image; these checks do not change the original cloud.
