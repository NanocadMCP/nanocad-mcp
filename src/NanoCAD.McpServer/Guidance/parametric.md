# Choose the representation and retained relationships

Choose the result identity and retained relationships before selecting a branch. The routes below are navigation, not a guarantee that every source/shape is eligible. Read the exact current variant and relevant source observations before writing. CE means create_entities, ME means modify_entities, and MS means modify_structure; entries in those tools are their exact kind or operation values.

| Intended result | Route | First useful read and retained meaning |
|---|---|---|
| A new independent shell body | CE Solid3d kind=shell_copy | inspect_solid_topology of the source; new result, source retained, no ShellFeature |
| A shell in the existing direct body | ME shell_solid | Current topology/face IDs; retains target handle, then refresh topology; inward/outward or closed-shell scope is branch-specific |
| A retained part shell or its thickness edit | ME add_model_shell / set_model_shell_thickness | History and, for opening selection, native model-face topology; inward ThicknessFeature with planar openings. Literal thickness edits remain available; persistent named Shell formulas are unavailable |
| A new independent Boolean result | CE Solid3d kind=boolean | Actual two source bodies and owners; new result, sources retained |
| A Boolean edit of the existing target | ME boolean_solid / boolean_region | Target/tools and actual owner/plane; retains eligible target and tool sources, not a replacement for a part-history editor |
| Independent repeated placements | ME copy / copy_transform_2d / polar_repeat; CE Solid3d kind=transform_copy | Selected source geometry/owners; new independent identities, no retained pattern dependency |
| Retained rectangular repetition of ordinary 2D curves | ME create_associative_rectangular_array / set_associative_rectangular_array | Eligible Model sources, then geometry.associative_array and its array_token; native array acquires sources, so use returned array/native_sources. Numeric edits replace only selected count/spacing expressions; expression text is unavailable |
| Retained circular or path repetition of ordinary 2D curves | ME create_associative_polar_array / create_associative_path_array and matching set_associative_* operation | Explicit source base_point; polar center/radius/start angle or committed path_handle. Native array acquires sources; read returned identities and array_token. After DWG reopen path_handle can be null with path_binding_observation while native items/count/spacing remain readable. Stored counts alone do not prove rendered regeneration; a pending controller/evaluation notice leaves that result unproved. An evaluation report says whether native evaluation occurred, not whether the requested item geometry is correct. set_associative_path_array assigns Path only when path_handle explicitly selects the desired current curve; omission never rebinds. Verify actual returned target identity and useful item geometry. Do not infer source following after reopening or substitute a remembered ID. These drawing arrays are separate from part-history patterns |
| Rectangular repetitions of a shared block definition | MS insert_block_array / set_block_array_properties | Definition from get_structure, then current MInsert array_token; one MInsertBlock and shared definition, not an AssocArray action network |
| Repeated features of one parametric part | ME add_model_rectangular_pattern / set_model_rectangular_pattern or add_model_circular_pattern / set_model_circular_pattern | Actual history/source features plus required direction/axis reads; retained native pattern. get_model_variables is needed for a supported named-driver edit |

Use declared value_unit and field units rather than inferring them from the drawing. For example, supported feature taper variables in set_model_parameter use degrees while dedicated taper_angle fields use radians; circular pattern angle_degrees is the step and count includes the seed. Planar profile coordinates can be local while returned source geometry is WCS. Convert from the observed frame explicitly and keep angle, length, count and identity roles distinct.

Honor specialized operations and preserve the intended existing part. A 2D assignment does not require a 3D model, history or sheet; use direct 3D when persistent dependencies are unnecessary and native parametric construction when the design needs them. Before selecting the feature sequence, recognize the formation rules supported by the supplied views, sections, dimensions and actual geometry: constant sections, rotational form, profile motion, local surface transitions, symmetry and repetition. Distinguish primary shape from finishing and genuinely complex curves/surfaces. Do not infer equal sizes, regular spacing or symmetry solely from a suggestive image. A compact construction plan for the connected group is sufficient; do not repeat this analysis before every command.

History should express useful changes through elementary profiles, meaningful dimensions and simple dependencies. Give independently changeable functional elements direct controls when combining them would bury those controls in a complex outline. An integrated profile remains suitable when its geometry and drivers are themselves simple; do not imitate every manufacturing step or maximize feature count. Judge a proposed decomposition by the expected edits: changing one element should not require unrelated endpoint formulas or needless changes to other elements. Meet the required shape and relationships first, then prefer simple geometry/dependencies and local editability; operation/call count is a later consideration. Let actual dependencies determine feature order; finishing is not subject to a universal last-step rule.

Choose the necessary independent dimensions and functional datums. Use geometric relations for orientation, coincidence, established symmetry and tangency. Position dependent features from their actual support/reference or a shared datum, and use arithmetic for real design relationships. A large formula network for every endpoint is a reason to reconsider the decomposition before writing. Recognize a geometric rule independently of its API representation, then use its applicable specialized MCP operation first. If that route is concretely unavailable or inapplicable, supported primitives may express the same rule through derived coordinates; retain actual required dependencies and disclose material differences. This does not authorize a custom solver, simulated native history or claims of native behavior the SDK cannot provide. Read actual drivers and consumers before editing; preserve useful existing identities/history rather than recreating the part to impose a preferred decomposition.

When the definition or construction method of a genuinely complex profile/surface is missing, consult authoritative geometry, profile data or vendor documentation as needed. Confirm applicability, units, orientation and required continuity; retain the specified profile and dimensions. Do not select a merely similar shape or simplify away required curvature. Routine elementary construction needs no additional research, and research does not replace resolving consequential missing design requirements.

Source drawing constraints, internal sketch controls, native feature variables and annotation dimensions are distinct. inspect_constraints reads the actual ACAD source network; inspect_sketch_constraints reads retained internal sketch relations; inspect_model_history reports native inputs, profiles, features and edit bindings; get_model_variables reads expressions, values and actual owning scope. A reference/driven measurement does not establish a driving relation. Before adding controls, identify what the existing anchors, coincidences, symmetry and dimensions already determine about position, orientation and size. Add independent design conditions for the remaining intended freedom; do not restate a relationship merely because another applicable command exists. Symmetry can already imply equality, orientation and endpoint placement. Whole-object Fix also fixes size, so it is unsuitable when that size must remain adjustable. Edit an existing driver rather than adding a second control for the same quantity. Initial coordinates alone are not constraints. Assembly mates are unavailable; coordinate placement is not a persistent relationship.

Treat a new "System is over constrained" notice as a problem in the affected constraint system to inspect before dependent construction. Read the actual sketch/relation identities and available native history notices, then remove or revise the unintended overlapping/conflicting condition while retaining the design requirement. A different notice that a redundant dimension became driven does not establish the same failure. Successful creation, healthy history, a stored expression or a reference/computed variable flag alone does not prove correct driving or solve the conflict; check the intended dependent geometry after a meaningful driver change. Do not assume that a historical notice disables the constraint family or that missing guaranteed Undo requires permission for ordinary task corrections.

When visible driving dimensions are requested, read inspect_sketch_constraints.presentation for the selected body/sketch, current edit mode, visibility_token and actual annotation IDs. ME set_model_sketch_visibility controls native sketch geometry with sketch_visible and existing annotation objects with dimensions_visible. Omit constraint_ids for all current dimensional controls or select actual constraint IDs for a subset; showing annotations enables their parent sketch. This operation does not enter/leave an editor, generate preview graphics, create replacement dimensions, solve or change drivers. A null DimId is an unavailable native annotation in that context, not a missing driving constraint; do not claim it was displayed. No standalone preview or editor-transition command is published for this purpose. Native layers/context can affect rendering; inspect the actual MCP image before claiming a useful visible result. A parameter list, MText legend or ordinary measured annotation does not satisfy a request for visible driving controls. Plan readable controls alongside simple feature decomposition; showing overlapping coordinate constraints alone is not a usable result.

For a source-driven bore layout, constrain the retained drawing Circle centers and diameters before creating their sketch profiles and features. set_drawing_dimension can revise one existing ACAD radius/diameter driver in a single part whose distinct selected Circle profiles share one projected sketch and feed native sweeps along retained drawing Line paths. Select the exact current source Circle and constraint/expression/value; the same native part rebuild retains peer circles, selected profile/sweep IDs, path bindings, taper drivers, feature order and readable owned data. Read retained_sweep_parts and refreshed source/history data, then inspect the resulting part and affected drawing. This numeric route does not propagate another drawing variable formula or edit an internal sketch solver; unsupported downstream feature types need their owning source-edit route.

Use the native parameter route matching the actual owner, active mode and units. set_model_parameter supports typed Dist first/second extrusion lengths, active extrusion/sweep taper angles in degrees, verified degree revolution angles, fillet/chamfer sizes, thread pitch/finite length, rectangular counts/steps, circular count/degree step, native offset-plane scalar, inward default shell thickness and observed native hole length offsets. Document User drivers may link supported controls through explicit arithmetic, except Shell thickness. Shell thickness supports reading and literal editing; persistent named-variable formulas are unavailable. For the other supported controls, propagate=true admits intended native variable cascades, and scope_handles explicitly selects affected/referenced bodies in one owning network. Counts are positive integers; native owners validate their actual control domain. value accepts a finite scalar in the actual verified control domain and requires a stored numeric literal; it does not silently replace a formula. Use expression for intentional formula replacement or arithmetic. Intentional healthy suppression is retained while active geometry rebuilds. Read control_kind, owner_kind and value_unit for actual shell/hole/taper bindings, and parameter_binding_notes when identification is unavailable. Hole diameter/depth/seat, other shell modes and unverified angular mappings need their owning editor; do not create an unrelated User variable and claim it drives such a field. Dedicated construction/edit taper_angle fields remain radians, while supported formula variables use their reported degrees. A second extrusion taper is independent only in active Different mode. Use named source/formula changes to retain design intent; replacing a formula with a literal in supported numeric taper, hole-offset or shell editors requires explicit replace_driver_formulas=true. Read current dependencies and resulting geometry rather than claiming a future driving effect from a stored formula alone.

# Symmetry and repeated features

For symmetric or repeated design elements, construct a useful seed feature/group once and prefer the applicable native mirror or pattern instead of duplicating its geometry independently. Choose symmetry planes and rotation axes from functional datums, with the intended clearances and exceptions planned for the whole group. Preserve the existing parameter/dependency intent; a direct task does not require a parametric history merely to repeat geometry.

add_model_circular_pattern and set_model_circular_pattern create/edit a retained native pattern of healthy original features of one part. Choose definition.axis: global_axis X/Y/Z, an existing same-owner work_axis, explicit fixed_axis WCS origin/nonzero direction, a native line, or a current same-part linear/circular edge. The legacy edge_token/axis_edge_id creation pair remains supported. A fixed native WorkAxis can express a shaft displaced from the global origin without a surrogate edge. Count includes the source occurrence; angle_degrees is the finite signed angular step, not total sweep. For a full ring of N instances use 360/N; retain its intended extent for a partial pattern. Native update decides validity of small, zero or full-turn steps; stored controls alone do not prove distinct repeated material. History and manufacturing_changes parameters expose axis.native_id, spacing_mode and reversed. To retarget the axis supply expected_axis_id; to replace original source_feature_ids supply expected_source_feature_ids, never generated source_item_ids. Optional expected_count/expected_angle_degrees strengthen value preconditions. Unchanged numeric values preserve owning formulas. For coupled count/angle relationships use set_model_parameter on exact owning variables, for example an angular expression 360/Count, then refresh actual values before another literal edit. Literal edits do not create that formula link; replacing a changed formula requires explicit replace_driver_formulas. This editor retains native step mode; range/fill interpretation and per-instance circular suppression are not published here. Review the whole repeated group, material, clearances and actual dependencies; use returned body_ref after rebuilding.

Use retained native mirror/rectangular-pattern routes for their supported source and datum bindings. add_model_rectangular_pattern accepts source_feature_id or an explicit source_feature_ids group of healthy preceding forming features of the same part and actual owner; a terminal extrusion is not required. For each direction use direction_x/direction_y with a native global_axis, existing work_axis, explicit fixed_axis origin/direction, line, or current same-part linear edge/token. Legacy direction_x_handle/direction_y_handle remain supported. Direction Lines need no preliminary projection; nonorthogonal directions are passed to the native pattern. A fixed selector creates retained native WorkAxis construction in the actual owner document without extra geometric constraints. Insertion follows the last model item before supported views and preserves intervening history. Original source_feature_ids remain separate from generated native_source_item_ids. For updates supply original expected_source_feature_ids and exact expected counts/steps; source_feature_ids intentionally replaces that group. To replace a direction also supply expected_direction_x_id or expected_direction_y_id from current history.parameters.direction_x/direction_y.native_id. Unchanged values preserve owning formulas; use set_model_parameter for a named expression or explicitly authorize literal replacement with replace_driver_formulas. Counts are positive native Int32 values per direction without a Cartesian-product cap; observation bytes still bound complete verification. Native step/range modes are read explicitly and this editor retains step mode. Per-position suppression keeps its existing single-source scope. Inspect the intended repeated material, clearances and dependencies. Independent copy/rotate/transform_copy placements do not create a retained pattern. For ordinary2D drawing geometry, use the separate native associative polar/path array routes; these do not establish part-history feature patterns.

# General construction and direct edits

Direct extrusion/revolution can consume an existing closed curve or Region with holes without rebuilding coordinates. Direct sweep consumes an existing profile/path; model_sweep keeps native feature history/path dependencies. A Helix is a trajectory, not a thread by itself. Choose profiles, axes, pitch, orientation and material operation from design requirements. Direct loft takes ordered sections and supported guides/path. Face press/pull offsets selected faces; it does not infer a bounded region from pixels. Read the selected schema and assess the meaningful result.

For a physical helical thread, use the supplied closed section and actual helical trajectory with native model_sweep, then perform the required material cut or join. Its published input uses an explicit plane/profile definition and path_handles; preserve the supplied section's shape and physical frame. A Helix may be stored as Spline: use that actual native path without replacing it by sampled segments. orientation=normal_to_path selects the native keep-angle behavior; its name is not a guarantee that the section is perpendicular to the path at every point. Check the resulting section orientation and helical material against the intended form, pitch, handedness, start/end positions and required clearance. A Thread feature or thread annotation alone is not evidence of physical helical geometry or compliance with a thread standard.

Plan the finite threaded interval from the actual drawing, shoulders, relief grooves and specified runout. Do not use the whole available Helix length by default. The swept section can extend axially beyond the path endpoints: account for that overhang when choosing the path start/end, and trim or clip an independent cutter to the intended thread zone when needed. Verify the actual first and last cut against those boundaries so material does not cross a relief groove or shoulder unintentionally.

For a separate cutter or added stock, use the applicable native Boolean subtract/union route and preserve or edit the original body as requested. For an eligible retained profile in an existing part, add_model_sweep_from_profile supports part_operation=cut or join with current profile/parent/token and path bindings. These are different ownership and history choices; keep the one required by the task. Refresh returned body references and inspect the actual groove or added material before claiming the requested thread is complete. A working sweep/Boolean construction alone does not establish the correct finite thread length or the correctness of the entire part.

An exact direct Solid3d sweep route returning NotImplementedYet does not establish that physical threads or native sweeps are unavailable. Use the applicable model_sweep route instead of repeating diagnostic probes of the same failed direct path. If the applicable native sweep cannot produce the required result, a native loft through physically ordered sections, rotated and advanced axially according to the intended lead and handedness, can be considered. Disclose that alternate construction and its geometry/dependency differences; do not silently replace the requested thread by cosmetic markings, dense faceted geometry or an unverified standard profile.

Use boolean_solid to edit a retained independent body; create boolean makes a new independent result and preserves source bodies. boolean_region edits an existing coplanar native Region with committed read-only tools. solid_containment and solid_interference answer their published questions; a negative interference result does not certify clearance.

slice_solid physically cuts a direct body with a WCS plane and returns both sides in solid_slice_results. Choose cuts from wanted material/stock, inspect both roles before removing excess and do not treat fragment separation as repair of a cut through wanted material. separate_solid turns already disconnected volumes into independent objects without cutting. create_section_view documents a cut while preserving model geometry.

For direct walls/stock, read a fresh inspect_solid_topology token. shell_solid uses positive thickness, side inward(default)/outward and exact remove_faces; an empty list requests a closed shell. Opening faces use native ShellBody; a closed shell uses native normal-offset/difference, disclosed by construction_method. offset_solid applies signed native normal distance, positive outward/negative inward, not scaling. These operations retain the direct target; shell_copy creates a new independent result. Read actual solid_stock_changes volume/WCS bounds, refresh topology and inspect important hidden cavities. These are not general wall-thickness/clearance measurements or parametric ShellFeature evidence. Shape feasibility and topology may change; started recovery/Undo is uncertain.

# Existing sketches, profiles and extrusion history

set_model_sketch_support binds an existing sketch to a retained native WorkPlane with definition.kind=workplane, plane_id and expected_datum_token, or creates the legacy offset document-plane support with reference_plane/offset. A reusable datum can remain document construction; its actual owner, part affinity and dependency scope decide admission. Optional legacy update_support_id edits that exact offset plane in place. Native support placement can move or rotate local sketch geometry and dependent features; it is not internal curve constraining. set_model_sketch_frame retains the same-part upstream work-point/axis route. Read actual support/frame and plan the intended dependent placement before writing.

For a retained sketch with a lost face support, recover_lost_support=true requires its observed expected_support_id and the chosen WorkPlane's current expected_datum_token. frame_reference_policy defaults to preserve, retaining its observed native point/axis/second-axis frame references. Explicit use_target_datum replaces those placement references with the chosen datum's actual native frame. Read recovery_preparation.frame_references when available and choose this mode only when replacing the old placement condition expresses the intended repair. These frame references are separate from the sketch's internal geometric/dimensional controls, which remain retained with its local elements, profile selections and dependent features. Neither policy permits guessing references or dropping other dependencies. An unavailable former WCS frame stays unknown; inspect the actual returned frame and intended rebuilt geometry, without assuming requested datum U/V axes or former placement were preserved. This policy field is available only for explicit lost-support WorkPlane recovery, not ordinary support changes or sketch creation.

To start an owned internal sketch and first feature, use model_extrusion with native_geometry, optional initial_constraints and region_point on its explicit WCS plane. Its native geometry accepts Line/Circle/Arc, complete clamped NURBS Spline and Ellipse; the selected area is verified through SDK region membership, including its real holes. Initial relations use input geometry keys; the requested area is selected after native solving. Its legacy profile branch remains a compact unconstrained native feature history. For a dependent sketch on an existing part, create_model_sketch accepts owned native_geometry together with committed drawing source_handles or same-part native reference_ids. Choose exactly one raw plane or support. Face support uses current planar model_face_id/face_token from inspect_solid_topology(include_native_model_faces=true); a workplane uses actual plane_id/datum_token from inspect_model_history and must have compatible actual owner/part affinity and native dependency scope. A reusable document WorkPlane is allowed without claiming body membership. reference_ids are actual native linked edge geometry from the current part topology, not B-rep IDs or drawing handles. For create_model_sketch, initial constraints can relate owned input keys to exact braced source GUIDs supplied in reference_ids; each source GUID binds its real new projection, with at least one owned operand. Use actual start/end/center points and the observed support frame for axis-based controls. Drawing handles, guessed projection IDs and invented aliases are not initial operands. For later mixed relations, use fresh returned native_inputs member IDs/binding_token through add_sketch_constraints. Projections are reference-only and keep their source/datum relationships. Read actual support/frame, peer profiles and current sketch_token; no zero remaining freedom or driving effect is inferred from a scalar or relation ID. Optional document sketch discovery remains paged.

create_model_profile_on_sketch selects a real profile on the retained sketch using its current token and an unambiguous material-region WCS point. Existing profiles and sources remain. Select the requested native outer/hole area, not a copied outer loop. add_model_extrusion_from_profile, add_model_sweep_from_profile and add_model_revolution_from_profile use the exact retained profile; add_model_loft_from_profiles uses an ordered set of existing native profiles without recreating their sketches; same-part sharing is assessed from actual forward_consumers, not a singular backlink. Existing foreign-body consumers cannot be transferred. Use fresh profile_ids metadata, expected_sketch_id/profile_token and current last_item_id. A new revolution needs an actual coplanar drawing Line axis_handle and positive angle_degrees up to360 in its stored direction. For loft, supply every section's current profile_id, expected_sketch_id and expected_profile_token in intended order. Keep supported same-part controls and consumers; select a regular loft, a retained center path, or guide rails according to the intended shape. Check each affected section and the resulting feature after a meaningful driver change. Refresh returned body/history/variables and inspect the connected result; native Undo/rollback is uncertain.

For a genuinely curved parametric section, create_model_sketch supports complete owned native Spline and Ellipse inputs in its WCS plane. Prefer analytic primitives for analytic geometry. A control-point NURBS needs its complete degree, controls, clamped knot vector and optional weights; Ellipse points mean center, major-axis endpoint and minor-axis endpoint, with angles in radians. Use create_model_profile_on_sketch to select the actual bounded region, including native curved holes, then consume its returned profile ID with the applicable extrusion/sweep/revolution route or as an ordered loft section. Do not approximate these profiles by short lines. Spline creation alone does not establish a retained relationship. Use smooth with explicit first_point/second_point start/end selectors when an open Spline and an adjacent curve need a smooth transition. Attach it to geometry whose endpoints and tangent continuation already express the intended shape. Change an existing named driver with set_model_parameter or a literal internal dimension with set_sketch_constraint_parameter, using fresh control tokens. After native sketch changes use the returned current member/relation IDs. At a meaningful checkpoint verify the rebuilt Spline, joined endpoint tangency and healthy profile/body. Smooth alone does not certify G2, a fully constrained sketch or every possible deformation. Ordinary drawing-source constraints use their separate ACAD route; their linked model-consumer admission does not automatically include Spline.

For internal native sketch relations, fix fixes one complete owned Line/Circle/Arc, including its size; fix_point fixes only the chosen endpoint or center. symmetric relates two Lines or two Circles about a separate actual Line supplied as third. Initial constraints use native_geometry keys or declared reference_ids; later add_sketch_constraints uses current native_inputs member IDs and binding_token. At least one of the paired elements must be owned, while projected references remain immutable. Use returned constraint_id and third_element_id plus actual observed first/second/third bindings; do not infer symmetry from mirrored coordinates. Keep the freedom needed for intended edits: fixing a whole Circle also fixes its radius, while fixing its center can leave a radius driver useful. Select real profile regions separately and check the dependent result after a meaningful driver edit.

create_model_profile makes unused native sketch/profile construction from committed coplanar Circle or closed Line/Arc sources in the selected healthy named Millimeters Model part's actual owner document. Unused construction may have no body host; read actual profile_ownership. inspect_model_history exact profile_ids reports real parent/support/frame/selected contour/source projections/native hosts/forming owner and fresh token. Optional include_document_profiles discovers identity pages; continue document_profile_cursor under the same revision when needed. The native owner can differ from the active DWG lookup container. A nullable projection planar support can mean a geometry-defined sketch plane, never an invented geometry ID.

add_model_extrusion_from_profile appends a native distance join/cut from the exact profile to the existing part. add_model_extrusion turns its explicit inline contour into independently owned native sketch curves and selects the declared closed contour. It adds no automatic design constraints. For a constrained, supported or reused profile, use create_model_sketch, create_model_profile_on_sketch and add_model_extrusion_from_profile with current IDs/tokens. Initial model_extrusion and retained drawing-source variants keep their separate scopes. Existing selected-part consumers and profile/source identities remain; nonempty host affinity must match the selected part. This does not transfer another part's construction. set_model_extrusion_profile rebinds that existing feature to an exact same-owner selected native profile with compatible oriented frame/support, including circular holes or multiple bounded Circle/Line/Arc regions. The replacement parent sketch must already be in the selected part's actual composition, or the profile must already have an actual same-part forming consumer. Same owner document alone does not acquire an unused outside sketch for this retained-feature rebind; that case is refused before the setter. Unused document construction remains valid for create_model_profile/create_model_profile_on_sketch and supported add-from-profile forming operations. Read fresh profile_ids tokens and actual forward_consumers: only the selected feature changes its profile; other same-part consumers retain theirs. It retains the feature and its dimensions/formulas and rejects dependency cycles before writing. Previous construction remains observed without a promise of release/reuse. Equal copied dimensions are not a shared driving link; bind intended new contour controls explicitly when future changes must follow them. Refresh affected history and drawings.

For annular or separated circular sections, set_model_profile_regions uses a consumed profile and fresh profile_region_ids region_token plus exact feature/profile/sketch/last IDs. Optional add_source_handles projects committed coplanar Circles into the retained sketch. Select each desired bounded cell with one distinct interior WCS region_points point. Whole circles must be separated or strictly nested; intersecting/tangent circles and adjacent cells requiring union need another adapter. Original sources/elements and native sketch/profile/extrusion/driver identities remain. This is not element deletion or internal MCS solving. Read actual area/hole loops and inspect the useful changed shape.

set_model_extrusion_extent has distinct termination and distance-mode branches. Use supported first-side end-face or through-all termination for that design intent; the Different/Symmetric branch does not remove terminal links or convert second-side termination. Read exact extrusion_extent_ids metadata and supply fresh extent_token/current feature/profile/parent/last IDs. Different uses positive-normal native_distance and negative-normal native_distance2 with separate taper angles in radians. Symmetric retains one native length/taper driver and symmetry relation; native_distance is SDK Distance, without an assumed total/half physical-span conversion. Read actual shape: body_bounds_wcs encloses the whole current part including later features, not an isolated extrusion.

Preserve unchanged formulas and keep requests consistent with native cascades. Explicit replacement of a changed formula requires replace_driver_formulas=true. Secondary driver IDs may be null before activation or remain property-only; do not invent variables or formula links. Use returned body_ref and refresh affected variables/history/drawings. Recovery/Undo is uncertain.

set_model_feature_suppressed suppresses or restores the selected native feature, including a nonterminal feature, without deleting its history. Pass the current feature_id and expected_suppressed, and the observed last_item_id as expected_last_item_id. No dependent suppression cascade is requested; unselected suppression choices, End-Of-Part, source/profile links and drivers remain while derived geometry rebuilds. Plan the actual dependency graph before suppressing a parent that active children require; restore prerequisites before their consumers. Restoring requires native safe-unsuppression eligibility. If pending history prevents an edit, use rebuild_model and read its observed state. When NeedUpdate remains in the selected feature's actual same-part dependent closure, use the suppression/restoration operation with fresh state to correct that feature's intended suppression; it does not waive Error/Unknown, foreign owners, unsafe restoration or unrelated pending constructions. Refresh the returned body/history and inspect the intended result; failed started work has no guaranteed rollback.

rebuild_model in modify_entities updates one existing parametric part without UI selection or manual activation. Use its current representation handle and observed expected_last_item_id. It accepts readable pending history and preserves every intentional suppression choice, source/order identity and stored variable definition. It requests the documented public native part rebuild once in immediate mode; contradictory design requirements and unsafe unsuppression still need an engineering correction. A committed receipt describes a finished rebuild attempt: check native_rebuild_accepted, model_healthy and unresolved_nodes before continuing dependent edits. Inspect actual affected dimensions, relations and geometry even when history is healthy. Reconcile any preceding unknown parameter change against its actual expression and geometry; a later rebuild does not change that original receipt. NeedUpdate alone is not a reason to ask the engineer to press Rebuild. If the same node remains unresolved, inspect that node and its actual prerequisites rather than repeating the rebuild or replaying the write. Native queue draining can also process other already queued host updates. Existing associative drawing views still require an appropriate final inspection/refresh.

Native part/construction snapshots can report NATIVE_PROXY_PRIVATE_STATE_UNOBSERVED for owned proxy storage. The observation retains exact resident identity/owner paths, public original class/DXF/application/flags, readable reference identities/states and XData/reactors/extensions, plus ordinary owned records. Stored proxy references can be null, erased, foreign or unavailable; NATIVE_PROXY_REFERENCES_UNRESOLVED reports that observation without claiming healthy targets or an empty inventory. Proxy-private payload bytes remain unobserved, with no claim of complete private-data preservation. Use the actual write outcome and verified controls, source relationships and geometry to assess the edit; these warnings alone do not disable the operation. Referenced objects retain their own ownership and are not granted an erase or modification scope by this observation.

reorder_model_feature changes a retained non-base feature's native predecessor. Read current feature IDs, native_order_before_id and last_item_id; predecessor_id means place the selected feature after it. Without expected_resulting_last_item_id, keep the terminal and End-Of-Part fixed. A terminal-changing request explicitly names the resulting last forming item and requires a part without drawing-view followers; native read-only eligibility checks the desired order and marker before writing. Sources, selected profiles, shared sketch, drivers and peer consumers remain retained. Refresh the returned body_ref/history and inspect the intended shape; this does not delete features, replace profiles, solve internal constraints or force invalid dependencies.

For an obsolete terminal native Fillet, Chamfer, Shell, Mirror, extrusion or revolution, delete_model_feature removes that actual feature and explicitly keeps the immediately preceding forming feature as the terminal. A selected unsuppressed terminal Mirror can be NeedUpdate while all retained constructions remain healthy; its original source features and datums stay retained. Read inspect_model_history with feature_deletion_ids for its current deletion_token, resulting_last_item_id and exact retirable_driver_ids; include [] when none are observed. The current scope keeps the base, other features, drawing sources, shared sketch/profile construction, formulas and observed constraints. For an extrusion/revolution, also pass expected_retained_profile_id from retained_profile.
